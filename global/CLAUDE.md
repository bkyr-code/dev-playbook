## Issue と PR の進め方（dev-playbook）
- GitHub の Issue を作る・進める・再開する依頼（例：「Issue #2 を進めて」「この Issue をやって」「〜の機能を追加したい」）は、依頼文に独自の手順が書かれていても、必ず issue スキル（/issue）で行う。依頼文の手順や条件は、スキルの手順に加えて守る。両者が衝突する場合は、進める前に確認する
- PR のタイトルと本文の作成・更新は pr-write スキルで行う
- 要件・設計・タスクなどを確定する前のレビューは spec-review スキルで、経緯を知らない独立したレビュアーに行わせる
