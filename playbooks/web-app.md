# Webアプリ開発 プレイブック

新しいWebアプリを作るときの進め方テンプレート。

---

## フェーズ1: 課題・要件定義

### 1. 課題定義
- 誰の問題を解くか
- 何が問題か
- 解決されたら何が変わるか

### 2. ターゲット定義
- どんな人が使うか（職種・状況・習慣）
- 自分用か・他人に使わせるか

### 3. 課題の解像度を上げる
- 現在のユーザーの行動フローを把握する
- 競合ツールを調べる（既存ツールの何が不満か）
- 課題を1〜2つに絞る（広げない）

### 4. スコープを決める
- **やること**（MVP）
- **やらないこと**（明示的に除外）
- テスト版 / 本番版 の区別をつける

---

## フェーズ2: 画面設計

### 5. 画面を会話で整理する
「アプリを開いたとき、最初に何が見えてほしいか？」から始めて順番に詰める。

- トップ画面に何があるか
- タップ/クリックで何が起きるか
- データの登録・編集・削除はどこからか
- ナビゲーション構造（サイドバー・タブ等）

### 6. 入力項目を決める
- 必須項目 / 任意項目 を分ける
- カスタマイズの必要性（固定 or ユーザーが編集可能か）

### 7. ドキュメント化
- `docs/REQUIREMENTS.md` — 要件定義
- `docs/WIREFRAMES.md` — ワイヤーフレーム（ASCII可）

**ワイヤーフレームの判断基準:**
- 画面数が少なく流れが単純 → 省略可
- 画面数10以上・条件分岐多い → 作る

---

## フェーズ3: 技術選定

### 8. 技術選定の観点
- プラットフォーム（Web / モバイル / デスクトップ）
- データ保存（localStorage / クラウドDB / ファイル）
- 開発速度 vs スケーラビリティ

**テスト版の推奨構成（Webアプリ）:**
```
フレームワーク: React + Vite
スタイリング:   Tailwind CSS
データ保存:     localStorage（DB契約不要）
言語:           TypeScript
ホスティング:   Vercel（無料）
```

---

## フェーズ4: 開発

### 9. 最小機能から作る
1. データの登録・一覧表示
2. 編集・削除
3. 集計・フィルター
4. エクスポート
5. 設定・カスタマイズ

機能を全部作ってから動かすのではなく、**1機能ごとにブラウザで確認**しながら進める。

- [ ] スコープ外が明示されている

- [ ] 入力項目が決まっている

### 技術選定完了の条件
- [ ] プラットフォームが決まっている
- [ ] データ保存方法が決まっている
- [ ] ホスティング方法が決まっている
